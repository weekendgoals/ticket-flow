What inspection found: `hireReviewer` (`workflows/run-epic.mjs:740-757`) awaits its first hire, `agent(…, { agentType: 'flow:ticket-reviewer' })`, with no `try`/`catch`, and its sanctioned fallback — one retry with a general agent given `REVIEWER_RULES` — is reached only when that call **returns** nothing, or returns something that is not a review. For an agent type the session has not registered, the Workflow runtime does not return: it throws, and an uncaught throw in the module body ends the whole workflow. So the fallback is unreachable in exactly the situation it reads as written for — a session where the plugin's agents are not registered. `run-epic.test.mjs` stubs `agent()` to return values (its two `flow:ticket-reviewer` assertions, `:227` and `:614`, check the type that was asked for, never a spawn that throws), so no test exercises this, and the run skill's step 4 sentence "A failed spawn gets one retry with the sanctioned fallback, then halts" is not true of this failure. It failed closed — nothing unreviewed was merged, `epic/deviation-routing` is still at `a4a26fa` — but it cost the run, and it would cost every run launched from a session without the plugin installed, at its first review. This epic's own `tickets.md` carries the wrong prediction, written by the planner when the delivery was re-planned: "each reviewer hire fails once and takes the driver's sanctioned fallback … a cost in spend, not in safety".
